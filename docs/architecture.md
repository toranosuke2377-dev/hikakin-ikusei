# アプリ構成

## 技術構成

- React 19
- TypeScript 7（strict）
- Vite 8
- Vitest + Testing Library
- ブラウザの `localStorage` によるオートセーブ・周回記録
- 外部バックエンド不要の静的Webアプリ

## ゲーム進行

全5章、各章12個の基本slotで進行する。各slotには必ず条件なしのfallbackイベントがあり、過去の選択、能力、関係、時代の流行に応じて優先度の高い別イベントへ差し替わる。

選択肢が `queueEvent` を指定した場合、通常の12slotとは別に続きの場面を挿入できる。これにより、同じ章でも一周あたりに読む場面数が変わる。

```text
現在の章・slot
  ↓
queueされたイベントがあれば優先
  ↓
章・slot・条件に合う候補を抽出
  ↓
二周目以降、周回限定の追加場面を低確率で挿入
  ↓（同じslotを維持）
固定イベントまたは最高priority帯を選択
  ↓
未閲覧イベントを高い重みで抽選
  ↓
選択結果を適用して次のslotへ
```

## 分岐データ

イベントは `src/data/chapter1.ts` から `chapter5.ts` に章別で定義する。周回向けの希少イベントは `src/data/replayEvents.ts`、エンディングは `src/data/endings.ts` に分離する。

炎上度を大きく上げる選択は `src/data/helpers.ts` で共通判定し、登録者を約50万人減らす。個々のイベントへ同じ処理を重複させないため、後から炎上場面を追加しても離脱コストと結果説明が自動で付く。炎上王の最終登録者は第5章の確定場面で約400万人へ収束する。

型定義は `src/game/types.ts`、条件判定は `src/game/condition.ts`、抽選・効果適用・章移行は `src/game/engine.ts` が担当する。

## 周回

終了時に次を周回記録へ保存する。

- 見たイベントID
- 到達したエンディング
- 発見した代表動画
- 最高登録者数
- 四皇時代への到達

次周では過去に見ていないイベントの抽選重みを高くする。さらに、初回には出ない周回限定場面を各章6件、合計30件用意する。二周目以降に未閲覧を優先して低確率で挿入し、見終えた後は同じslotの本編へ戻るため、重要な節目を置き換えない。プレイ開始時には世界の流行を二つ選び、同じ選択でも結果や登場人物が変わるようにする。

## 素材差し替え

素材がない状態でも、CSSによるプレースホルダーで全編をプレイできる。完成素材は `public/assets` 以下へ指定名で置くだけで自動表示され、コンポーネントやシナリオの変更は不要。

- 背景・イベントCG: WebP
- 透過立ち絵: WebP
- ループ映像: MP4

`npm run assets:manifest` で、シナリオが参照する素材一覧を `docs/asset-manifest.md` に生成する。

## セーブ

選択直後にオートセーブする。途中でブラウザを閉じても、次の場面から再開できる。周回記録は現在のセーブと別に保存するため、新しい人生を始めても消えない。

セーブデータにはバージョン番号を持たせ、互換性のない変更時に古いデータを安全に無視できるようにする。
