# BEAT TO THE TOP — ヒカキン育成ゲーム

所持金2万円、登録者0人、武器はビートボックスだけ。無名の投稿者「ヒカキン」の人生を第三者の立場から選び、日本一のYouTuberを目指す、PCブラウザ向けの選択式育成アドベンチャーです。

全5章、1プレイ約1時間。どの動画を作るかだけでなく、仕事、体力、信用、仲間、炎上、原点との向き合い方が数章後まで影響します。画像・動画素材が未配置でも、デザイン済みのプレースホルダーで最初から5種類の結末まで遊べます。

> 本作品はフィクションです。登場する人物・団体・名称・出来事は架空のものであり、実在する人物・団体とは一切関係ありません。

## 現在の完成範囲

- 全5章、60個の基本進行スロット
- 章別シナリオ217イベントと、初回から出現する希少イベント31件
- 合計248イベント、721選択肢
- 5種類のエンディングと、条件付きの「四皇時代」差分
- 登録者、所持金、体力、表現力、制作力、ビートボックス、信用の育成
- 原点、野心、疲労、炎上傾向、活動方針、人間関係、選択履歴による長期分岐
- 数字が変化した時期と、登録・解除・収益・支出の理由を結果画面に表示
- 三択の前に場面固有の問いを置き、過去の決断で変化した場面には分岐理由を表示
- プレイごとに変わる2種類の時代トレンドと、初回から出る未閲覧の希少場面を優先する抽選
- 選択直後のオートセーブ、再読み込み後の続きから再開、周回記録
- 素材未配置時のフォールバック表示と、素材キーからの自動読み込み

シナリオとゲーム本体は完成済みです。次の制作工程は、キャラクターデザイン、背景、イベントCG、短いループ映像の共同制作と差し替えです。

## 起動方法

Node.js 22 LTSを推奨します。

```bash
npm ci
npm run dev
```

表示されたローカルURLをPCブラウザで開きます。

本番用ビルドと確認は次のとおりです。

```bash
npm run build
npm run preview
```

生成物は `dist/` に出力されます。Viteの `base` は相対パスに設定しているため、静的ホスティングへそのまま配置できます。

## 操作

- 選択肢をクリック、または数字キー `1`〜`3` で選択
- 「能力・人間関係」から、能力、現在の方向性、時代トレンド、主な関係、代表動画を確認
- プロフィールは `Esc` キーでも閉じられる
- 「保存して終了」でタイトルへ戻り、「つづきから」で再開
- タイトルの「記録」で、発見済みエンディング、周回数、発見イベント数、最高登録者数を確認

「最初から」は未完了の現在プレイを破棄しますが、エンディングなどの周回記録は残ります。

## 開発コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバーを起動 |
| `npm run build` | TypeScriptの検査後、本番用ファイルを生成 |
| `npm run preview` | 本番ビルドをローカル確認 |
| `npm run test` | Vitestを一度実行 |
| `npm run test:watch` | テストを監視実行 |
| `npm run check` | strict TypeScript検査と全テストを実行 |
| `npm run balance:report` | 6方針×100seedの自動プレイ結果を再生成 |
| `npm run assets:manifest` | シナリオが参照する全素材パスを再生成 |

完成確認の基本コマンドは次の2つです。

```bash
npm run check
npm run build
```

## ゲームの構成

```text
src/
├── App.tsx                 画面遷移、セーブ、章進行、結末表示
├── components/             物語画面、結果、能力、画像・動画表示
├── data/
│   ├── chapter1.ts         第1章イベント
│   ├── chapter2.ts         第2章イベント
│   ├── chapter3.ts         第3章イベント
│   ├── chapter4.ts         第4章イベント
│   ├── chapter5.ts         第5章イベント
│   ├── replayEvents.ts     初回から出現する希少イベント
│   └── endings.ts          5エンディング
└── game/                   型、条件判定、抽選、効果、保存、検証、シミュレーション

public/assets/              後から差し替える画像・動画
scripts/                    素材一覧・バランス報告の生成
docs/                       企画、分岐、設計、監査、引き継ぎ
```

イベントは章とスロットに紐づき、条件に合う候補の中から選ばれます。重要な節目は固定しつつ、過去の選択、能力、関係、時代トレンド、閲覧履歴で周辺の出来事と結果が変わります。希少場面も初回から出現できます。詳しくは [アプリ構成](docs/architecture.md) と [全5章の分岐設計図](docs/branch-map.md) を参照してください。

## 画像・動画の差し替え

素材がなくても全編をプレイできます。完成素材は、イベントの `visual` が示す相対パスに合わせて `public/assets/` 以下へ置くだけで表示されます。コードやシナリオを変更する必要はありません。

```text
背景・イベントCG  .webp
透過立ち絵         .webp
ループ映像         .mp4 または .webm
タイトル画像       public/assets/ui/title_hero.webp
```

最新の必要素材一覧は次のコマンドで `docs/asset-manifest.md` へ出力します。

```bash
npm run assets:manifest
```

命名規則、表情差分、推奨寸法は [素材差し替えガイド](public/assets/README.md) を参照してください。次回の共同制作手順は [次回の壁打ち](docs/next-session.md) にまとめています。

## セーブデータ

セーブと周回記録はブラウザの `localStorage` に保存され、外部サーバーへ送信されません。

- 現在プレイ: `beat-to-the-top:save`
- 周回記録: `beat-to-the-top:meta`

互換性のないデータは保存バージョンで判定します。完全に初期化する場合は、ブラウザの開発者ツールまたはサイト設定から、このサイトのローカルストレージを削除してください。

## 公開前の重要事項

ゲーム内には「実在する人物・団体とは一切関係ないフィクション」である旨を表示しています。ただし、免責表示だけで、人物名、経歴、外見、商標、パブリシティー、名誉、著作物、音楽などに関する問題が解消されるとは限りません。

現在の設定は実在の人物・団体を強く連想させます。一般公開、配布、宣伝、収益化を行う前に、専門家への相談も含めて権利と表現を確認し、必要に応じて名称、外見、経歴、事件、ロゴ、ゲーム画面、楽曲を十分に独自化してください。画像生成では実在人物の似顔絵を目標にせず、本作独自のキャラクターデザインを正本とします。
